# 投标资质审查预警：先验证，再推广

## 我的判断

企业希望减少资质审查未通过造成的无效编标工时。发放数据里，**资质信息的同步时间较旧**是一个可供前置检查的信号；但数据没有失败原因、实际到期日或预警后的处理记录，因此不能证明同步刷新能够避免失败，更不能把历史关联直接写成已节省的工时。

我建议先把“提交时距资质最后同步达到 20 分钟”做成**试点检查条件**：系统先刷新资质，核对真实有效期和投标要求；只有刷新失败、资质过期或信息不一致时才转人工处理。不要对所有命中记录直接投入一次 15 工时的人工预警。

## 看到了什么

数据仅使用任务发放的 `bid_qualifications.csv`，SHA-256 为 `0daf4d0afacaf7b877dfeb0a10dae1c68eb0e42e450d3b4608207cc0a5825dd4`。原始文件 1,010 行，有 48 行是逐字段完全重复；去重后是 962 个不同 `audit_id`。其中 855 个通过、78 个未通过、29 个未回传结果。**未回传记录不进入通过率或失败率分母**。原始审查记录不上传到公开仓库；持有任务数据的人可按下文复算。

`submitted_at` 带东八区时区，`cert_synced_at` 为 UTC；脚本先按带时区时间计算两者差值，再比较分钟阈值。只用 2026-09-01 至 09-05 的已出结果记录比较候选阈值（10、15、20、25、30、40、50 分钟），按“全部命中的失败都被避免”这一乐观假设下的净工时上限选规则；20 与 25 分钟并列时取更早提醒的 20 分钟。2026-09-06 至 09-07 完全留作时间外验证。

| 样本 | 已出结果 | 命中 20 分钟规则 | 命中者未通过 | 未命中者未通过 | 命中的未通过占全部未通过 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 选规则的前五天 | 656 | 115 | 39/115（33.9%） | 17/541（3.1%） | 39/56（69.6%） |
| 留出的后两天 | 277 | 52 | 11/52（21.2%） | 11/225（4.9%） | 11/22（50.0%） |

后两天的命中组风险仍较高，但低于前五天，说明不能把训练期效果直接外推。后两天命中组未通过率的 Wilson 95% 区间约为 **12.2%–34.0%**，样本量仍小。

单看 `valid_days_left <= 3` 不适合直接触发昂贵预警：前五天为 16/77 未通过，后两天只有 3/28。即使假设这 3 次都能避免，按每次预警 15 工时、每次失败 90 工时计算，后两天净值上限仍是 **-150 工时**。`valid_days_left = 0` 的已出结果记录中有 20/23 通过；这一字段不能单独当作“已失效”的证据。

## 工时账怎么算

题目给出每次未通过约损失 **90 工时**，每次提前预警资质失效约花费 **15 工时**。若把 15 工时保守地视作每条命中记录都要人工核验的成本，则：

`净工时 = 90 × 实际避免的未通过次数 − 15 × 实际人工预警次数`

在留出样本中，52 次人工预警花 780 工时；命中组历史上有 11 次未通过，全部避免最多节省 990 工时，**净值上限仅 210 工时**。要真正净节省，至少须避免其中 **9 次**。我们目前不知道能避免几次，所以 **210 工时不是已实现收益，也不是预测收益**。此外，题目中的 15 工时是“资质失效预警”口径，将其用于所有“同步时间较旧”的人工核验只是敏感性假设，落地前必须量实测成本。

## 做什么、做到什么程度

1. **试点，不自动群发人工预警。** 在提交前的资质检查界面显示“资质信息需刷新”：当可用的最后同步时间距提交时点达到 20 分钟时，先请求最新资质记录。若提交环节尚不能取得该时间戳，需要先补采集，而非用事后时间戳伪装实时预警。
2. **核对真实问题。** 比对最新证书状态、实际到期日、资质类别和招标文件要求；对确实过期、缺失或无法同步的项目交给资质负责人处理。现有 CSV 不含这些字段，不能用 `valid_days_left` 自行推断证书失效。
3. **保留操作和成本记录。** 记录 `audit_id`、命中时间、刷新前后同步时间、复核结论、失败原因、人工耗时和最终审查结果，按事业部与资质类型检查漏报。29 条当前未回传结果需继续跟踪，不能默认通过。
4. **用试点评价能否省工时。** 对没有已知硬性失效证据的软提示做分阶段或随机试点；已知失效的项目全部照常处理。比较提示组与对照组的未通过率和实际人工耗时，再估计避免的失败次数，代入上式。若实际净工时不为正，降低人工触发范围或停止人工预警。

## 复现

需要 Python 3.10+，只用标准库。把任务发放的 CSV 放到仓库的 `data/bid_qualifications.csv`，然后在仓库根目录执行：

```bash
python analyze.py
```

脚本验证列名、时区、结果值和重复 `audit_id`，生成 [`results.json`](results.json)。结果包括所有候选阈值在训练期的计数、选定规则的时间外验证、95% 区间和工时盈亏平衡点。可用 `--input` 和 `--output` 指定其他文件；若同一个 `audit_id` 对应不同内容，脚本会报错，避免任意保留一条。

## 边界

- 只有 7 天数据，后两天仅 22 次未通过；没有长期、跨团队的稳定性证据。
- 记录的是审查结果，不是失败原因，也没有实际干预记录；无法识别哪些失败能被资质刷新或预警避免。
- 20 分钟是本样本选出的试点阈值，不能当作制度规定。预警成本、同步刷新成本和 90 工时损失都需要业务实测。
- CSV 仅含本题发放字段；没有引入或伪造外部数据。
